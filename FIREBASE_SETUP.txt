إعداد متجر KABOUSH للمزامنة بين الأجهزة
=========================================

GitHub Pages يستضيف ملفات الموقع فقط. Firebase يحفظ المنتجات والأقسام والعروض
وبيانات التواصل والصور حتى تظهر على أجهزة العملاء.

1. أنشئ مشروع Firebase، ثم أضف تطبيق Web وانسخ إعداداته إلى firebase-config.js.
   املأ apiKey وauthDomain وprojectId وstorageBucket وmessagingSenderId وappId.
2. فعّل Authentication > Email/Password وأنشئ حساب صاحب المتجر بالبريد
   K.STORE@GMAIL.COM وكلمة المرور التي اخترتها. لا تحفظ كلمة المرور في ملفات
   الموقع ولا تنشئ صفحة تسجيل حسابات عامة. أضف نطاق GitHub Pages إلى Authorized
   domains.
3. تم وضع UID حساب الإدارة الموجود في إعدادات المشروع داخل firebase-config.js
   وقواعد الأمان المرفقة. تأكد من أنه يطابق UID الظاهر في Firebase Authentication.
4. أنشئ Cloud Firestore وفعّل Firebase Storage. انسخ firestore.rules إلى
   Firestore > Rules وانشرها كما هي. ثم انسخ storage.rules إلى Storage > Rules
   وانشرها كما هي. لا تستبدل القواعد بقواعد تسمح بالكتابة العامة.
5. ارفع ملفات الموقع إلى جذر مستودع GitHub. فعّل النشر التلقائي من
   Settings > Pages، ثم اختر Deploy from a branch، وحدد main والمجلد /(root).
   ينشر GitHub Pages تلقائيًا بعد كل تحديث للفرع. ملف pages.yml في الجذر
   مرجع للإعداد فقط؛ GitHub Actions لا يشغّل ملفات workflow من خارج
   .github/workflows.
6. افتح رابط الموقع المنشور ثم admin.html، وسجّل الدخول ببريد وكلمة مرور حساب
   Firebase الذي أنشأته.
7. عند أول دخول، ينقل الموقع المنتجات المحلية الناقصة إلى Firebase دون
   استبدال المنتجات الموجودة بالفعل على السحابة، حتى لو كانت مجموعة products
   تحتوي على مستند تجريبي. بعد ذلك تتم مزامنة تغييرات اللوحة والعروض تلقائيًا
   على أجهزة العملاء. أضف العرض من قسم "إضافة عرض"، وأدخل السعرين لحساب نسبة الخصم
   تلقائيًا؛ ويمكن تحديد تاريخ بداية ونهاية اختياريين وإضافة صورة برابط أو
   برفع ملف من الجهاز.

مهم: لا تفتح admin.html وindex.html بالنقر المزدوج كملفات file://؛ المتصفح
يعزل التخزين المحلي بين الصفحتين، ولن تظهر العروض المحفوظة في لوحة الإدارة
على الصفحة الرئيسية. افتح الموقع من رابط GitHub Pages أو عبر خادم محلي.

ملاحظات الأمان والتشغيل:
- لا تضع كلمة مرور أو Service Account JSON أو GitHub token في ملفات الموقع.
- Firebase Web config وownerUid إعدادات عميل عامة؛ قواعد Firebase هي التي
  تمنع غير صاحب UID من تعديل المنتجات والعروض والإعدادات أو رفع الصور.
  تشمل قواعد Storage المحدّثة رفع صور العروض؛ أعد نشرها بعد تحديث ملفات الموقع.
- قراءة كتالوج المنتجات والصور عامة للزوار، والكتابة مقصورة على UID المحدد.
- قد يتطلب Firebase Storage تفعيل الفوترة وفق متطلبات Firebase الحالية.
- لا تحذف قواعد الأمان أو تستبدلها بقواعد تسمح بالكتابة العامة.
- لا تبدأ إدخال بيانات فعلية قبل إكمال الخطوات ونشر القواعد والتحقق من ظهور
  حالة الاتصال بـ Firebase في لوحة الإدارة.
